# DDTC LMS: documentation set for Claude Code

Copy this whole folder into the root of the `ddtc-lms` repository (so `CLAUDE.md` is at the root). Then start Claude Code with: "Read CLAUDE.md and docs/PHASES.md. Start Phase 0 by writing the plan and wait for my approval."

| File | What it is |
|---|---|
| `CLAUDE.md` | Rules and the phase protocol Claude Code follows every session |
| `docs/BUILD_PLAN.md` | Master specification v1.7 (decisions D01 to D40, all phases, acceptance) |
| `docs/DECISIONS.md` | Locked decisions, ADR log, and the decisions you still have to make (O1 to O26) |
| `docs/PHASES.md` | How phases work, the phase list and tracker |
| `docs/phases/` | One file per phase (0 to 14) with build items, tests and exit gate |
| `docs/TESTING.md` | How every phase is tested before moving on |
| `docs/ARCHITECTURE.md` | How the system works, with a preference check |
| `docs/DATA_MODEL.md` | Tables, constraints, storage buckets |
| `docs/SECURITY_AND_ACCESS.md` | Permission matrix, trusted functions, sign-in and upload rules |
| `docs/DESIGN.md` | Design system v3.0: colours, Inter, components, logos, Google button |
| `docs/RESPONSIVE.md` | Device and responsive standard |
| `docs/UI_FEEDBACK.md` | Toasts, floating action buttons, skeleton screens |
| `docs/ACCEPTANCE.md` | The 15-step acceptance journey |
| `docs/RUNBOOK.md` | Production readiness and operations |
| `docs/INPUTS.md` | What DDTC must supply, with owner and date |
| `docs/references/` | Where Mobbin reference notes go |
| `docs/prototype/` | Clickable prototype and trial logins |
| `assets/brand/` | Logos, icons and favicons |
