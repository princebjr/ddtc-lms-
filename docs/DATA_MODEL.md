## 5. Final data model

All tables have `id uuid` primary keys (except where noted), `created_at`, and `updated_at` maintained by trigger. RLS is enabled on every table with no default access.

| Table | Key columns and constraints |
|---|---|
| profiles | id (= auth.users.id, FK), id_number, first_name, second_name, email, contact_number, role, can_create_courses, account_status, profile_completed, profile_image_file_id. Role, status and can_create_courses are not user-editable. `id_number` (ADR-008): six digits, 100000 to 999999, unique; assigned by a trigger from `private.id_number_seq` through `private.id_number_for()` (a one-to-one shuffle); a second trigger refuses any change. `branch_id` (D42, ADR-010): nullable FK to `branches` (ON DELETE RESTRICT); learners only and only an open branch (`profiles_guard`, 22023); the learner updates their own (column grant), an AAL2 administrator updates any learner's under `profiles_update_admin_branch` and may change nothing else of theirs (42501); every change writes `profile.branch_changed` (from and to names, who) through `profiles_audit_branch`. `course_roster` returns `branch_name` to the course's lecturers. |
| branches | id, name (unique, 1 to 80 characters), position (unique), is_active (default true), created_at. Seeded: Kasoa C.P, Affumkrom - Nsawam, Sampa, Amanfrom, Kumasi, Atwitwiriso (positions 1 to 6). Signed-in users read every row; no client inserts, updates or deletes; a branch in use cannot be deleted (D42). |
| system_settings | key (PK), value (jsonb), updated_by, updated_at. Holds all values marked default. |
| courses | title, course_code (unique), description, learning_objectives, category, cover_image_file_id, created_by, status, missing_as_zero, archived_at. |
| course_lecturers | course_id, lecturer_id, permission_level, assigned_by. Unique (course_id, lecturer_id). |
| course_enrollments | course_id, learner_id, enrolment_status, enrolled_at, enrolled_by. Unique active enrolment per (course_id, learner_id) via partial index. |
| lessons | course_id, title, content (sanitised HTML), position, publication_status, created_by. Unique (course_id, position). |
| file_objects | id, bucket_name, storage_path (unique), original_filename, safe_download_filename, detected_mime_type, file_size, duration_seconds, uploaded_by, status (PENDING, VALIDATED, REJECTED, DELETED, DELETE_FAILED), resource_type, resource_id, checksum, validation_error, uploaded_at, validated_at, deleted_at. Server-generated paths; no client write access to `status` or any validation field. `delete_attempts` and `last_delete_error` count failed removals (D18; `cleanup_failures()` lists files at 3 or more for administrators). A SUBMISSION_FILE has `resource_id` = its submission and its version in its path; one never sent is removed after 24 hours (ADR-013). |
| lesson_audio_files | lesson_id, file_object_id, uploaded_by, title, position, lifecycle_status (ACTIVE, SUPERSEDED, ARCHIVED, DELETED), superseded_at, deleted_at, deleted_by. ADR-007: up to 10 ACTIVE files per lesson, each at a distinct position 1 to 10 (a deferrable exclusion constraint, so reorders and deletions move several at once); history and deleted rows have no position; a DELETED row keeps who deleted it and when, and its file is removed from Storage. File validation state comes from `file_objects`. |
| lesson_attachments | lesson_id, file_object_id, uploaded_by, title, position, removed_at, removed_by. Deleting (ADR-007) sets removed_at and removed_by; the row is kept and the file is removed from Storage. Validation state comes from `file_objects`. |
| lesson_progress | learner_id, lesson_id, completion_status, completed_at. Unique (learner_id, lesson_id). |
| grade_categories | course_id, name, weight (0-100). Weights per course must total 100 before first release. |
| assignments | course_id, lesson_id (nullable), category_id, title, description, content_type (TEXT, AUDIO, TEXT_AND_AUDIO), text_instructions, instruction_audio_file_id, due_at, allow_late, max_marks (>0), accepted_formats (array, checked; always TEXT and AUDIO, optionally PDF and DOCX, ADR-009), grading_criteria, publication_status, created_by, published_at, archived_at. CHECK constraints enforce instruction-type rules. |
| assignment_versions | assignment_id, version_number, title, description, content_type, text_instructions, instruction_audio_file_id, due_at, max_marks, accepted_formats, grading_criteria, changed_by, change_reason, created_at. Preserves published snapshots and material edits. |
| submission_extensions | assignment_id, learner_id, extended_due_at, granted_by, reason, revoked_at, revoked_by. One standing extension per (assignment_id, learner_id) (partial unique index where revoked_at is null). Set, changed and taken back only through `submission_extension_set` and `submission_extension_remove` (ADR-013): the date is after `due_at` and in the future; a taken-back extension is kept with who and when; learners read only their own standing one; `private.effective_due_at` ignores taken-back ones (D13). |
| submissions | assignment_id, learner_id, status (DRAFT, SUBMITTED, GRADED, REOPENED), current_version, is_late, score, feedback, graded_by, graded_at, grade_release_status (DRAFT, RELEASED), released_at. Unique (assignment_id, learner_id). DRAFT means uploads are waiting and nothing has been sent (current_version 0; CHECK). Score between 0 and the assignment's max_marks, up to two decimals, for any writer (trigger `submissions_grade_guard`; max_marks never drops below a given score); a released grade changes only with a reason. Phase 9 (ADR-014): released_score, released_feedback, released_by hold what the learner sees (copied on release; a later change waits in score and feedback until released again); RELEASED means the learner sees the current grade. Clients never read the grading columns directly: grades go through `assignment_results`, `submission_review` and `my_grade` (released only); nobody writes directly (`submission_submit`, `grade_save`, `grade_release`, `grade_reopen`). |
| submission_versions | submission_id, version_number, text_answer (plain text, at most 20,000 characters, ADR-013), submitted_at, is_late, client_request_id. Unique (submission_id, version_number) and (submission_id, client_request_id): the same request returns its version instead of making a second. Never updated or deleted, by anyone (trigger). |
| submission_files | submission_version_id, file_object_id (unique), file_role (AUDIO, PDF, DOCX, OTHER). Validation/deletion state comes from `file_objects`. A file joins a version only in the transaction that submits it, only a VALIDATED file of that version's own submission, at most `max_files_per_submission_version` (5) per version (trigger); never updated or deleted. |
| grade_change_history | submission_id, event (SAVED, RELEASED, REOPENED), previous_score, new_score, previous_feedback, new_feedback, changed_by, reason, changed_at (clock time). Written by trigger on every grade change (drafts included), release and reopening (ADR-014); refused for UPDATE, DELETE and TRUNCATE to everyone; the server may only add. Read by the course's lecturers and AAL2 administrators through `submission_review`. |
| notifications | recipient_id, notification_type, title, message, related_entity_type, related_entity_id, link_path (a path inside the app, for View), deduplication_key, read_at, created_at. Unique deduplication key where present. Created in Phase 9 (ADR-014) with types GRADE_RELEASED and GRADE_UPDATED; Phase 11 adds the other D21 types. The recipient reads their own and may set read_at only. |
| notification_deliveries | notification_id, channel (EMAIL), status (QUEUED, SENT, RETRYING, FAILED, SUPPRESSED), attempts, provider_message_id, last_error, next_attempt_at, sent_at, updated_at. |
| notification_preferences | user_id, email_enabled (boolean). |
| audit_logs | actor_id, action, entity_type, entity_id, metadata (jsonb), created_at. Insert by triggers and Edge Functions only; no UPDATE or DELETE for anyone. |
| retention_holds | scope (SUBMISSION, LEARNER, COURSE), scope_id, reason, placed_by, placed_at, released_at. |
| retention_runs | started_at, finished_at, mode (DRY_RUN, LIVE), eligible_count, deleted_count, failed_count, details (jsonb). |

## 6. Storage buckets (all private except noted)

| Bucket | Path pattern | Who writes | Who reads |
|---|---|---|---|
| lesson-audio | {course_id}/{lesson_id}/{file_id}.{ext} (MP3, M4A, WAV, and WebM or Ogg recordings, ADR-013) | Course lecturers (via pipeline) | Course lecturers, ACTIVE or COMPLETED enrolled learners (published lesson, VALIDATED file), administrators |
| lesson-attachments | {course_id}/{lesson_id}/{file_id}.{ext} | Course lecturers | Same as lesson-audio |
| assignment-instructions-audio | {course_id}/{assignment_id}/{file_id}.{ext} | Course lecturers | Course lecturers, enrolled learners (published assignment), administrators |
| learner-submissions | {assignment_id}/{learner_id}/{version}/{file_id}.{ext} | The learner, through the pipeline only (D18; `submission_prepare_upload` checks D10, the kind and the 5-file limit) | The learner (own files, sent or waiting); the course's lecturers and AAL2 administrators (files of submitted versions only); VALIDATED only |
| profile-images | {user_id}/{file_id}.{ext} | The owner only | Any signed-in user (low sensitivity) |
| course-covers | {course_id}/{file_id}.{ext} | Course lecturers | Any signed-in user who can see the course |


Replacing a profile image or course cover creates a new `file_objects` row; the old object is removed by the `cleanup-files` job. That job never touches lesson audio or attachments in use, instruction audio, or files of submitted answers; an answer's file that was never sent is removed after 24 hours (ADR-013).
